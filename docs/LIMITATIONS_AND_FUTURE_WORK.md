# 연구 및 운영상 한계와 확장 방향

## 그때 본 가격을 얼마나 정확히 재현했나

월말마다 볼 수 있는 행을 제한했지만, 그 행의 값은 사후 수정된 World Bank Snapshot에 들어 있습니다. 단일 수집본에서 과거 최초 발표본(Vintage)을 복원할 수 없고, 다음 달 말 `available_at`도 실제 최초 공표시각을 관측한 값이 아니라 가정입니다. 그래서 당시 의사결정의 근사인 pseudo-real-time으로 해석합니다. 2020-07 HRW 등급 정의 변경은 문서에서 확인한 경계입니다. 구조단절이나 품질이 가격에 미친 효과는 별도 검증이 필요합니다. [데이터 및 As-Of 계약](DATA_AND_ASOF_CONTRACT.md)

## 같은 방법을 다른 시장에 적용하면

단일 원재료·시장·기간을 분석했습니다. 미국 Gulf 기준가격은 지역과 업체가 다른 납품계약의 단가를 그대로 대표하기 어렵습니다. 과거 OOF와 순차 예측은 target, 학습 이력, 시간 의존성을 공유합니다. 월별 오차와 비용 차이를 독립 표본처럼 세면 근거가 실제보다 많아 보입니다.

같은 Validation에서 SARIMAX를 비교하고 선호했기 때문에 선택편향이 남습니다. LightGBM 정책의 가상 비용이 낮은 조건이 있었다는 결과는 고정 기본 사양을 바꿀 별도 검증으로 사용하지 않았습니다. 운영 민감도도 같은 가격 경로에서 가정을 바꾼 사후 진단입니다. 각 조건을 독립 시장 반복이나 정책 성공 확률로 해석할 근거는 없습니다.

## 불확실성은 어디까지 계산했나

명목 80% 구간은 Validation에서 실제 가격을 그보다 적게 포함했습니다. 시간 의존성과 겹치는 target이 있는 환경에서 rolling conformal 보정의 교환가능성 기반 보장을 적용할 수 없습니다. Joint bootstrap의 가중치는 경험적 재표집에서 나오며, 같은 pool의 seed를 바꿔도 독립 OOS 관측이 생기지는 않습니다.

시나리오가 표현하는 불확실성은 가격입니다. 실제 수요·지연 분포와 가격·공급의 상관은 추정하지 않았습니다. 계획 CVaR는 주어진 경로에서 동일 계획의 고비용 꼬리를 비교하는 지표입니다. 장기 실현 시장위험, 수요 충족 보장, 기업 절감액이나 인과효과를 추정하려면 다른 검증 설계가 필요합니다. [불확실성과 공동 가격 시나리오](UNCERTAINTY_AND_SCENARIOS.md)

## 장부에서 중요한 운영 가정

수요·업체·할증·용량·재고·비용은 가정입니다. 초기재고 취득비를 매몰비용으로 처리하고 잔존가치 0, 말기편차 비용, Runoff 3개월과 유한 계획창을 적용했습니다. 이 선택은 발주와 총비용에 영향을 줍니다. 말기 패널티는 그 차이를 관리하기 위한 비용 항목이며 자산가치를 추정한 값은 아닙니다.

고정 3개월 계획창에는 H4..6 예측이 없습니다. 공표 lag2를 검토하려면 새 시점에 맞춰 예측과 OOF를 다시 생성해야 합니다. LP에서 시나리오 간 발주·물리 흐름을 공유한 방식은 비예견적이지만 경로에 따라 계획을 수정하는 적응형 다단계 모형의 범위까지는 다루지 않습니다. 계획 폐기 W=0도 보수적입니다. 확정 물량이 창고 용량을 넘을 때 엔진은 초과분을 처리할 수 있지만 제한 LP는 infeasible일 수 있습니다. [구매 의사결정 최적화](PROCUREMENT_OPTIMIZATION.md)

## 현재 확인한 실행과 다음에 필요한 근거

합성 Native/Legacy 통합은 입력을 통제한 소프트웨어 검증입니다. 실제 Source Export·Seed Runtime은 NOT_VERIFIED / ACCESS_APPROVAL_REQUIRED이며 최종 Holdout은 미평가·잠금 상태입니다. clean checkout의 계약 테스트는 과거 전체 613개 로컬 archive 검증보다 좁은 범위입니다. Python 원천·세션 guard는 API 경계에서 적용됩니다. OS 격리와 데이터 이용권한은 별개이며 코드 라이선스는 소유자가 선택하기 전까지 미지정입니다. [재현성 안내](REPRODUCIBILITY.md)

1. 먼저 승인된 과거 전용 Export의 생성 근거와 외부 hash를 대조하고 실제 adapter 및 Legacy 연결을 확인합니다. 최종 연구평가를 진행하려면 새 digest·역할·달력·실패 조건을 정하고 별도로 단회 승인을 받아야 합니다. 평가 경로가 하나라면 반복 시장위험을 식별하는 데에는 여전히 한계가 있습니다.
2. Coverage·tail, HRW 정의 변경, 공표 지연, Runoff와 말기 근사는 무엇을 비교할지 먼저 정한 뒤 원래 결과와 나란히 검토합니다.
3. 다른 원재료·시장과 실제 운영자료에서 결론을 비교하려면 해당 자료의 이용권한과 지역·업체별 납품 조건이 필요합니다.
