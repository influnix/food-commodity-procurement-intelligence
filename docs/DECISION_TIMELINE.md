# 의사결정 타임라인과 정보 계약

## 월별 이벤트의 순서

`t`는 의사결정이 이루어지는 달입니다. 모든 event timestamp는 UTC로 저장하고 월말 순서는 별도 `event_sequence`로 보존합니다. 아래는 가상 월별 거래 시계이며 실제 기업의 체결 관행을 재현한다는 뜻은 아닙니다.

1. 월 `t` 시작: 과거 주문 중 실제 납품월이 `t`인 주문을 수령합니다.
2. 월중: 월 `t` 수요가 실현되고 출고합니다. 부족은 lost sales로 기록합니다.
3. 월말 정산: 납품월 `t`에 대한 지수 연동 대금을 회계적으로 확정합니다. 실제 공개가 다음 달이면 지급도 뒤로 이동할 수 있으나 MVP는 납품월 귀속비용으로 계산하고 이자/현금흐름은 모델링하지 않습니다.
4. 월말 `t`, 결정 직전: 허용된 신규 공표 정보와 과거 주문의 상태/미도착 사실, 월 `t`말 재고를 정책에 공개합니다. 지연의 미래 잔여기간은 공개하지 않습니다.
5. 월말 `t`, `decision_at=d_t`: 재고·알려진 pipeline·수요 예측·공급계약·가격 예측으로 발주합니다. 리드타임 `L>=1`이므로 가장 빠른 납품은 `t+1`입니다.

평가 엔진이 사후 귀속을 위해 안 가격·비용이 정책의 “정산 이력”을 통해 먼저 새지 않도록 합니다. 공개된 청구서가 시장지수를 역산 가능하게 한다면 해당 청구서도 `available_at` 이전에는 context에서 숨깁니다.

## 가격의 관측 시점

시장가격 `P_m`은 월 `m`의 월평균 지수입니다. 월초나 발주 순간의 거래가능 가격으로 취급하지 않습니다.

Day 0 보수적 가정: `available_at(P_m) = 월 m+1의 말, 결정 직전`입니다. 따라서 `d_t`에서 최신 허용 관측은 `P_(t-1)`입니다. 이는 World Bank의 실제 고정 공표 규칙이라는 주장이 아닙니다. 원천의 개별 공표 이력이 확인되면 timestamp 기반으로 대체합니다. 결측·미공표이면 더 오래된 마지막 허용 관측을 사용하고 horizon을 다시 계산합니다.

예: 2020-06 말 결정에서는 원칙상 2020-05까지의 관측만 사용하며, 2020-07/08/09 납품가격을 예측합니다. 이 날짜는 규칙 설명용이며 실제 데이터 확보를 뜻하지 않습니다.

## 비즈니스 horizon과 모델 horizon

Day 2 구현: `evaluation/splits.py`에서 origin·feature cutoff·target·horizon과 target 성숙도 마스크를 생성하고, `data/availability.py`의 guarded store에서 실제 값의 가용성을 검사합니다. 현재 holdout target은 2024-10~2026-09로 잠겨 있습니다. 첫 holdout origin 2024-09까지 validation label이 공표돼야 하므로 주 validation의 마지막 target은 2024-08입니다. 변경 이유와 수식은 [분할 설계](SPLIT_DESIGN.md)에 기록했습니다.

- 구매 목표: `P_(t+1), P_(t+2), P_(t+3)`의 점예측과 q10/q50/q90.
- 정보 지연 때문에 최신 관측 `P_(t-1)`부터는 각각 **2, 3, 4 step ahead**입니다.
- 재귀 모델은 관측되지 않은 `P_t`를 중간 예측해 연결하고 실제 `P_t`를 넣지 않습니다. direct 모델도 같은 target/date 계약을 따릅니다.
- 출력은 정수 horizon만으로 해석하지 않고 `decision_at`, `last_observed_month`, `target_month`, `delivery_offset`, `steps_from_last_observation`을 함께 저장합니다.
- Seasonal Naive도 target `m`에 대해 `P_(m-12)`의 해당 origin 가용성을 검사합니다.
- 가격 상승 위험은 `Pr(P_(t+h) > P_(t-1))`로 정의합니다. 아직 모르는 `P_t` 대비 상승 위험과 혼동하지 않습니다.

## 정보 집합

| 항목 | `d_t`에 허용 | 엔진 전용 / 허용하지 않음 |
|---|---|---|
| 가격 | `available_at <= d_t`인 과거 가격 | 미래 납품월 실제 지수, 미공표 `P_t` |
| 계약/견적 | 현재 유효 premium·용량·lead 분포, 관측된 견적 | 미래 실제 견적 또는 나중에 바뀐 계약 |
| 수요 | 100 t/월 계획값 또는 당시 작성된 forecast | 미래 실제 수요; MVP에서 완전정보 수요는 주 분석에 사용하지 않음 |
| 재고/pipeline | 현재 on-hand, 과거 발주량, 현재까지 납품/미납, 알려진 ETA | 미래 실제 지연 추첨 결과 |
| 날씨 | 공표·집계가 완료되어 가용한 과거 기상만 | 미래 관측 및 미완성 월 집계; 근거 없는 미래 날씨 예측 |
| 시나리오 | validation에서 고정한 충격 분포와 확률 | 평가 경로의 충격 발생 월·크기·숨겨진 seed |

납기와 수요의 알려진 확률은 모델 가정이고, 실제 추첨값은 별개입니다. Risk-Aware가 받은 가상의 planning scenario와 평가 엔진의 실제 외생 경로를 공유하지 않습니다.

## 발주·납품·가격 확정

월말 `k`의 공급업체 `s` 발주 `q_(s,k)`는 기본적으로 월초 `k+L_s`에 납품됩니다. 납기 지연 `delta_(s,k)`가 있으면 실제 수령월은 `r=k+L_s+delta_(s,k)`입니다.

실제 매입단가: `c_(s,k) = P_r * (1 + premium_s)` (USD/t), 실제 매입비용: `c_(s,k) * q_(s,k)` (USD). 수령 시 전량 구매하고 취소는 허용하지 않습니다. 계약 premium은 발주 시 알려져 있으나 `P_r`와 지연 `delta`는 미래 불확실성입니다. 월별 지수 단위가 USD/t로 검증되기 전에는 이 식을 실행하지 않습니다.

추천 대안 비교: 발주 시 확정견적 계약에서는 `c_(s,k)`가 결정 시 알려진 견적이고 가격 위험의 전파가 달라집니다. 이 경우 실제 미래 가격으로 현재 견적을 구성하면 누수입니다. 별도 계약 유형의 민감도로 구현하며 주 계약과 혼합하지 않습니다.

## 공표 지연·수정·날씨에 대한 한계

Day 1 확인: 원본은 `Updated on October 02, 2026`이며 최종 관측월은 2026-09입니다. 한 번의 snapshot으로 과거 모든 달의 공표 지연을 추정하지 않습니다. 기존 `d_t`에서 `P_(t-1)`까지 사용하는 가정을 유지하고 CSV의 `available_at`을 실제 발표시각으로 오해하지 않도록 `availability_basis`를 함께 저장합니다. 원본에는 2026-03에 SRW의 2023/2024 가격을 수정했다는 설명이 있어 역사적 수정 위험이 실재함을 확인했습니다. 자세한 증거 위치는 [출처 기록](WORLD_BANK_SOURCE.md)에 있습니다.

- 최신 파일의 과거값은 수정되었을 수 있습니다. `retrieved_at`은 당시 공표 시점이 아닙니다.
- 최초 내려받은 파일에 vintage ID·SHA-256을 붙이고 재다운로드는 새 snapshot으로 둡니다. 실제 과거 vintage가 없으면 `latest_vintage_pseudo_real_time`을 명시합니다.
- 그 경우 과거의 `available_at`은 관측 월+가정 지연으로 추정한 값입니다. `availability_basis=assumed`로 표시하고 역사적 재현이라고 주장하지 않습니다.
- 지연 1/2개월 민감도를 비교하되 holdout을 보고 지연을 고르지 않습니다. 2개월 지연에서는 모델 target까지 3/4/5 step이 필요합니다.
- NASA 사용 시 좌표·생산지역 근거·생육시기·파라미터 단위·UTC/LST·공표 지연·월별 평균/합산을 먼저 확정합니다. 일별 값의 월 집계 `available_at`은 구성 관측의 최댓값과 집계 완료 시점 이후입니다.
- 주 분석의 미래 날씨는 미사용합니다. 기후평년이나 별도 발행된 예보는 출처와 발행일을 가진 대안 실험으로만 허용합니다.

구현 시 검증할 것: 미래 한 행을 넣으면 거부하는 as-of 테스트, 미래값을 바꿔도 과거 발주가 불변인 테스트, 현재 월 실제값을 숨긴 다중 step forecast, 지연 수령과 정산월 일치.

## Day 6 구현된 시나리오·시뮬레이터 경계

공동 OOF는 `o+3<=t−1`과 세 실제 공표 timestamp<=d_t를 확인한 뒤 세h를 함께 재표집합니다. 개별h calibration 성숙도를 완전 경로로 간주하지 않습니다. `ScenarioSet.for_policy`는 현재 origin의 planning 세트만 허용하고 evaluation 경로는 거부합니다. 다른seed의 같은pool 재표집은 독립/OOS 평가가 아닙니다.

Toy 엔진은 월초 입고·수요·폐기 후 월말 정책을 호출합니다. DecisionContext는 현재 재고·알려진 수요계획·계약·promised/overdue pipeline·t−1 이하 공표 가격만 포함합니다. 실제 미래 도착월·delay·수요·가격 경로·evaluation seed는 없습니다. 수령월 매입비는 월말 accrual로 엔진 ledger에만 기록하며 현재 P_t를 역산할 수 있는 단가/비용을 정책에 전달하지 않습니다. 다음 달에야 해당 지수의 공표 조건을 만족합니다.

## Day 7 Receding-Horizon

Forecast-Aware는 이현재context와현재origin의점예측만받아t+1~min(t+3,T)의계획을풉니다. 현재t의q만실행하고미래q는계획로그에만남깁니다. 다음달에는새공개재고/pipeline/예측으로다시풀며이미확정된주문은입고상수로유지합니다. overdue입고는명시적으로다음달로예상하고실제미래delay를읽지않습니다.

명목lead의예상수령월가격으로LP비용을계산하며최대delay는신규주문의계획창허용성검사에별도적용합니다. 계획말기비는매월실제비용에청구하지않습니다. 실제수령월의실현가격은엔진만매입비귀속에사용합니다. 실제Forecast adapter는현재origin의검증된point만export하고정답/오차/score를정책에넘기지않습니다.
